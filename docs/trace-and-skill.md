# Trace and skill review

Each analysis run has ordered events with type, status, parent relationship, attempt, safe error category, duration and artifact references. One `TraceContext` follows the lead into spawned durable teammates and their tools. PostgreSQL events retain only SQL hashes, policy/EXPLAIN summaries, approval IDs, bounded result counts and artifact IDs. Payloads are recursively redacted and bounded before storage. Replay reads persisted events; it does not re-execute a model or database query. `GET /api/runs/{run_id}/replay` returns a versioned, self-contained manifest containing the run, task, correlated agents, approvals, artifacts, candidate Skill and sequence-integrity checks.

A workflow can become a candidate only after a completed trace with successful tool evidence is explicitly accepted by a human. Acceptance idempotently creates one durable `CURATOR` agent whose tool allowlist is empty. It receives bounded structured evidence—not raw prompts or tool output—and is told to treat it as data rather than instructions. The evidence includes tool names, attempts, recovery categories and artifact counts so the generated workflow can retain the proven safety gates. The curator runs static safety validation and writes one disabled candidate. Provider, eligibility and validation failures remain durable agent terminal states. Human review may approve or reject a candidate, but approval deliberately leaves `enabled=false`.

Provider timeouts, network failures, rate limits and upstream errors retry at most twice with exponential backoff. Retryable tool failures are counted per normalized call signature; the model receives remaining-attempt metadata and then an explicit fallback instruction. Identical failed calls and total tool actions remain bounded.
