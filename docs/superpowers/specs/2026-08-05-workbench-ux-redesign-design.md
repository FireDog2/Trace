# 迹析工作台体验重构设计

## 目标

把当前“项目下拉框 + 中间静态面板 + 右侧无限增长对话”的页面，重构为以分析项目为中心、三栏职责清晰、长内容互不拖累的工作台。

## 已确认的问题

- 1280 × 720 视口下，右侧长对话把整个页面撑到约 5600px，中间内容结束后出现大面积空白。
- 项目被收进原生下拉框，用户无法快速浏览、切换和理解当前项目上下文。
- Agent 的主要文字输出全部留在对话区，中间工作台只有计划、事件和产物列表，信息价值偏低。
- 左、中、右三栏共用页面滚动，输入框和重要状态容易离开视口。

## 设计决策

### 1. 视口内三栏工作台

桌面端使用 `100dvh` 固定工作台高度。项目栏、分析画布和对话栏各自滚动，任何一栏的长内容都不能改变其他栏高度。

```text
┌────────────项目栏────────────┬──────────────分析画布──────────────┬────────分析协作────────┐
│ 品牌 / 模型                  │ 任务标题 / 状态                     │ 标题 / 收起             │
│ 项目列表                     │ 当前结论                            │                        │
│ 当前项目数据                 │ 计划 + 执行记录                     │ 独立滚动的消息流         │
│ 当前项目任务                 │ 分析产物                            │                        │
│                              │                                      │ 固定输入框               │
└──────────────────────────────┴──────────────────────────────────────┴────────────────────────┘
```

右侧对话栏可收起。收起后，中间画布获得额外宽度；重新展开不会丢失对话位置和输入内容。

### 2. 左侧项目管理

- 用纵向项目列表替换原生下拉框，当前项目有明确选中态。
- “新建项目”作为列表标题旁的直接操作，展开后显示紧凑输入框。
- 数据和任务只属于当前项目，并以可扫读的文件行、任务行展示。
- 左栏内部滚动，品牌、模型入口和新建项目入口保持清晰。

### 3. 中间分析画布

- 顶部保留任务目标和状态，控制字号，避免长标题占据半屏。
- 新增“当前结论”，显示最近一条 Agent 输出，承担结论摘要和下一步提示；内容较长时可展开或收起。
- “分析计划”和“执行记录”保持并列，但降低固定最小高度，按真实内容生长。
- “分析产物”继续作为代码、表格、图表和报告的长期容器。
- 中间画布独立滚动，不再跟随对话长度产生空白。

### 4. 右侧分析协作

- 对话栏由固定头部、独立滚动消息区、待审批区和固定输入框组成。
- 工具消息默认折叠成一行摘要，避免 JSON 日志占据大量空间；用户与 Agent 消息保持可读宽度。
- 输入框始终留在视口底部，用户无需滚到消息末尾才能继续追问。
- 对话栏提供明确的收起按钮；收起态在中间画布右上角提供“展开对话”。

### 5. 视觉系统

- 颜色：墨蓝 `#102A32`、证据绿 `#0B8F7A`、纸面白 `#F7F8F5`、分隔灰 `#D9E1DE`、提醒琥珀 `#B96A16`。
- 字体：中文正文使用系统无衬线字体；数字、状态和事件编号使用等宽字体。
- 背景网格仅保留在分析画布，并降低对比度；项目栏和对话栏使用干净纸面。
- 特色元素是贯穿计划、事件和产物的“证据脊柱”，强调每条结论都能回到步骤和产物。

## 响应式行为

- `> 1180px`：完整三栏，对话栏可收起。
- `760px–1180px`：项目栏缩窄，对话栏作为覆盖式抽屉打开，中间画布保持主要宽度。
- `< 760px`：项目栏和对话栏都成为抽屉，主画布单列；所有操作保留键盘焦点和可访问名称。

## 测试与验收

- 在存在大量消息时，页面本身不出现由对话造成的纵向滚动；三栏滚动互不影响。
- 对话输入框在长消息列表下仍可见。
- 项目以列表方式显示并可直接切换，新建项目流程仍可用。
- 中间工作台显示最近 Agent 结论、计划、执行记录和产物。
- 对话栏可收起和重新展开。
- 现有模型配置、数据上传、任务切换、审批和发送消息行为保持可用。
- 通过现有前端测试、TypeScript 构建，并在 1280 × 720 和窄屏视口完成浏览器检查。
