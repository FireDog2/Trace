# TRACE 对话与产物工作台设计

## 目标

将 TRACE 工作台重构为面向数据分析 Agent 的三栏界面：左侧管理项目上下文，中间承载分析对话与 Agent 执行轨迹，右侧集中展示可持久化的最终产物。视觉语言以用户提供的参考图为基准，采用深海军蓝侧栏、明亮白色工作区、蓝紫色主操作色和低对比边框。

本次设计替代此前“左侧项目、中间分析、右侧聊天”的信息架构。产品英文名继续使用 **TRACE**；用户创建的项目名称不做自动翻译，示例和系统预置名称使用英文。

## 已批准的桌面结构

```text
┌──── 项目上下文 22% ────┬──── 分析对话 38% ────┬──────── 最终产物 40% ────────┐
│ TRACE                   │ 任务问题与运行状态    │ 报告 / 图表 / 数据 / 代码       │
│ 项目                    │ Agent 执行轨迹        │ 结论、可视化、表格和来源说明    │
│ 数据来源                │ 审批与工具详情        │ 打开或导出已登记产物            │
│ 模型                    │ 追问输入框            │                                  │
│ 新建分析 / 分析任务     │                       │                                  │
└─────────────────────────┴───────────────────────┴──────────────────────────────────┘
```

- 左栏默认占桌面宽度的约 22%，保证长项目名和数据来源名称可读。
- 中栏约占 38%，是提问、追问和理解 Agent 执行过程的主要区域。
- 右栏约占 40%，为报告和图表保留足够阅读宽度。
- 三栏独立滚动；页面总高度固定在视口内，避免长对话拉长整个页面。

## 左侧：项目上下文

左栏保留 TRACE 当前项目的真实结构，不照搬参考图中的业务模块。信息顺序为：

1. TRACE 品牌与工作区说明。
2. 项目列表，当前项目使用蓝色选中态。
3. 数据来源，统一展示三种来源类型。
4. 模型配置，显示当前供应商、模型和配置状态。
5. “新建分析”主操作。
6. 当前项目的分析任务历史。
7. 当前本地工作区身份与设置入口。

### 数据来源

数据来源统一放在同一分组内，每一行必须显示类型、名称和状态：

| 类型 | 示例 | 状态语义 | 使用方 |
|---|---|---|---|
| 数据库连接 | PostgreSQL | 已连接、连接失败、未连接 | 数据分析与执行 Agent |
| 文件上传 | `operations.csv` | 已上传、已加载、解析失败 | 数据分析与执行 Agent |
| 业务知识库 | Business Knowledge Base | 已索引、索引中、索引失败 | Knowledge Agent |

“添加数据源”是统一入口，后续可分流为连接数据库、上传 CSV / Excel、添加业务知识库。状态不能只依赖颜色，必须保留文字说明。

当前仓库只具备 CSV / Excel 上传 API。此次前端重构接通现有文件上传；PostgreSQL 和业务知识库按照真实能力展示入口或状态，不创建虚假的成功流程。完整连接、鉴权、同步和索引能力需要单独的后端 API 设计与实现。

## 中间：分析对话

中栏取代原来的分析画布，包含以下区域：

- 顶部显示“分析对话”、任务状态、累计运行时间和辅助操作。
- 用户问题使用清晰的蓝紫色消息块，Agent 内容保持白色或浅灰面板。
- Agent 执行轨迹作为对话中的结构化区块，按顺序展示任务拆解、数据读取、口径检索、结构检查、代码生成、安全检查、执行、综合结论和质量复核。
- 工具详情默认折叠；安全检查、审批请求和错误步骤可展开。
- 每一步显示名称、耗时和状态。运行中、完成、失败必须同时使用图形和文字表达。
- 输入框固定在中栏底部，支持继续追问，并提供少量与当前分析相关的快捷提示。

Knowledge Agent 的口径检索属于执行轨迹的一步。当项目存在已索引的业务知识库时，轨迹应显示检索命中数量或使用的口径来源；没有知识库时不展示虚假命中。

## 右侧：最终产物

右栏用于浏览任务产生的持久化产物，不再承载聊天。顶部使用四个标签：

- 报告：Markdown 或 HTML 报告、核心结论和来源说明。
- 图表：图表产物及其标题、描述和打开操作。
- 数据：派生数据集、预览和下载入口。
- 代码：Python、SQL 或其他可复现代码产物。

默认打开“报告”。如果任务没有对应类型的产物，显示明确的空状态和产生该产物的下一步，不使用示例数据冒充真实结果。

产物列表和预览必须来自 `task.artifacts`。类型映射以现有 `artifact_type` 为基础：

- `markdown_report` 与报告类 HTML → 报告。
- `chart` → 图表。
- `source_dataset` 与 `derived_dataset` → 数据。
- `python_code`、SQL 和其他代码类型 → 代码。

导出或打开操作仅在存在真实 `content_url` 时可用。当前没有合并导出 API 时，不显示看似可用的“导出 PDF”或“导出 Excel”操作。

## 模型配置弹窗

模型配置从左栏模型行打开。弹窗沿用参考图的明亮视觉体系：

- 宽度约 680–760px，桌面端分为供应商列表和连接配置两列。
- 当前供应商使用蓝色描边和浅蓝背景。
- Base URL、模型和 API Key 保留现有行为。
- 取消和保存操作固定在底部；保存是唯一高优先级按钮。
- 移动端改为单列，字段和操作必须完整可达。

## 视觉系统

### 颜色

- 左栏背景：深海军蓝 `#0C1732`，分组表面 `#152344`。
- 主工作区：白色 `#FFFFFF` 与冷灰 `#FBFCFE`。
- 页面背景：雾蓝灰 `#EAF0F8`。
- 主操作与选中态：蓝紫 `#416CEF`。
- 成功状态：绿色 `#31BD78`。
- 风险和错误：珊瑚红 `#EF6060`。
- 主文字：墨蓝 `#172238`；次级文字：冷灰蓝 `#7F8B9D`。
- 边框：`#DFE5EE`。

颜色只承担强调，不作为唯一状态信号。

### 字体与密度

- 正文和操作使用系统无衬线字体栈，优先 `Inter`、`Segoe UI` 和中文系统字体。
- 产品名、标题和关键数字使用中等或半粗字重；避免全页面粗体。
- 左栏保持紧凑但可读；中栏轨迹行高度约 42–46px；右栏正文按报告阅读密度排版。
- 圆角控制在 6–12px，避免大面积胶囊和过度玻璃效果。
- 阴影只用于浮层、输入框和当前选中面板。

## 响应式行为

- `>= 1320px`：显示完整三栏。
- `980–1319px`：左栏保持约 280px，中栏占主空间，右栏改为可打开的产物抽屉。
- `< 980px`：默认显示中栏；项目上下文和最终产物分别通过左右抽屉进入。
- `< 640px`：对话轨迹隐藏次要耗时字段，弹窗改为单列接近全屏。

任何断点下都不能通过缩小文字来强行保留三栏。

## 数据与交互边界

- 不修改现有项目、任务、消息、审批、模型配置和产物 API 的语义。
- 不伪造 PostgreSQL、知识库、导出 PDF 或导出 Excel 的成功行为。
- 本次 UI 重构允许增加前端分类、标签页和响应式抽屉状态。
- 数据库连接和业务知识库的完整功能需要新的领域模型和 API，不包含在本次视觉重构中。
- 用户创建的项目和文件名称原样显示；只将产品品牌和系统示例名称设为英文。

## 测试与验收

- 前端测试验证桌面 DOM 顺序为项目上下文、分析对话、最终产物。
- 左栏同时存在数据库、文件和知识库的类型表达，并为每种类型提供文字状态。
- 中栏保留消息发送、审批处理和执行事件显示。
- 右栏按产物类型切换标签，只显示真实任务产物。
- 模型配置、项目切换、文件上传和任务切换继续工作。
- 现有前端测试、TypeScript 检查和 Vite 构建全部通过。
- 在 1440×900、1280×720、1024×768 和 390×844 视口检查布局。
- 检查键盘焦点、空状态、长项目名、长消息和没有产物的任务。
