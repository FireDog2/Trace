# 分析输入互斥显示设计

## 目标

消除“分析目标”和“给分析 Agent 留言”同时出现造成的选择困惑。任意时刻只允许用户看到一个分析输入框，并让输入框的含义由当前任务状态决定。

## 交互规则

1. 当前项目没有选中任务时，只显示工作台中央的“分析目标”输入框，用于创建新分析任务。
2. 创建任务或选中已有任务后，中央区域显示任务计划、执行记录和产物；右侧显示“给分析 Agent 留言”，用于补充口径、调整目标和继续追问。
3. 切换到没有任务的项目时，回到第一种状态。
4. 不再使用禁用的对话输入框暗示未来功能；未进入任务时，整个右侧对话栏隐藏。

## 布局

- 无任务：页面为“项目导航 + 宽工作台”两列，工作台占据原主区域和对话栏空间。
- 有任务：页面恢复“项目导航 + 任务工作台 + 对话栏”三列。
- 窄屏保持纵向布局；由于两个输入区域互斥，不会出现上下重复输入框。

## 实现边界

- 由 `App` 根据已加载的 `task` 决定是否渲染 `Conversation`。
- 根布局增加有无对话栏的状态类，CSS 据此切换列定义。
- `Conversation` 不再需要 `disabled` 属性，因为组件只在有任务时存在。
- 不改变任务创建、消息发送、审批、模型配置或后端 API。

## 验收与测试

- 无任务时，“分析目标”存在，“给分析 Agent 留言”不存在。
- 有任务时，“给分析 Agent 留言”存在，“分析目标”不存在。
- 现有任务工作台、审批和模型配置测试继续通过。
- TypeScript 检查和生产构建通过。
