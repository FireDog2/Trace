# 单一分析输入框测试用例

## 测试目标

验证“分析目标”和“给分析 Agent 留言”互斥显示，确保用户在任意时刻只需要面对一个分析输入框。

## 测试前准备

1. 启动后端：`data-analysis-agent serve --host 127.0.0.1 --port 8765`。
2. 启动前端：`npm --prefix web run dev`。
3. 在浏览器打开 `http://127.0.0.1:5173`。
4. 在左侧 `MODEL ROUTE` 中完成模型配置。

## TC-01：空项目只显示分析目标

**前置条件：** 当前项目没有分析任务。

**操作步骤：**

1. 新建一个项目。
2. 不创建任何分析任务。
3. 观察页面中央和右侧区域。

**预期结果：**

- 页面中央显示“分析目标”输入框和“开始分析”按钮。
- 页面右侧不显示“分析协作”栏。
- 页面中不存在“给分析 Agent 留言”输入框。
- 主工作台使用除左侧导航以外的全部可用宽度。

## TC-02：创建任务后切换为对话输入

**前置条件：** 当前项目没有分析任务，模型已经配置。

**操作步骤：**

1. 在“分析目标”中输入“分析本季度各区域利润变化”。
2. 点击“开始分析”。
3. 等待任务工作台出现。

**预期结果：**

- “分析目标”输入框消失。
- 中央显示任务标题、分析计划、执行记录和分析产物。
- 右侧显示“分析协作”和“给分析 Agent 留言”输入框。
- 页面中仍然只有一个分析输入框。

## TC-03：选中已有任务只显示对话输入

**前置条件：** 当前项目至少存在一个分析任务。

**操作步骤：**

1. 在左侧“分析任务”列表选择任意已有任务。
2. 观察中央工作台与右侧栏。

**预期结果：**

- 中央显示所选任务的持久化计划和产物。
- 右侧显示该任务的消息历史和“给分析 Agent 留言”。
- 不显示“分析目标”输入框。

## TC-04：从有任务项目切换到空项目

**前置条件：** 项目 A 有任务，项目 B 没有任务。

**操作步骤：**

1. 先选择项目 A，确认右侧对话输入框可见。
2. 切换到项目 B。

**预期结果：**

- 项目 A 的任务工作台和右侧对话栏消失。
- 页面切换为项目 B 的“分析目标”输入框。
- 不残留项目 A 的消息、审批卡或任务产物。

## TC-05：窄屏不出现重复输入框

**前置条件：** 浏览器宽度小于 720px。

**操作步骤：**

1. 在空项目状态检查页面。
2. 创建或选择一个任务后再次检查页面。

**预期结果：**

- 空项目状态只显示“分析目标”。
- 有任务状态只显示“给分析 Agent 留言”。
- 两种状态均不存在上下排列的重复分析输入框。
- 输入框和按钮没有横向溢出。
